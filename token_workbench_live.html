口径说明：输入＝prompt_tokens，输出＝completion_tokens，缓存命中＝cached_tokens（上下文中被复用的部分）， 净输入＝输入 − 缓存（真正新增计费的输入）。模型名取自系统提示 This conversation is powered by <model>， 任务名由 trace 中的会话 UUID 关联 workbuddy.db。注意：traces 存在 100KB 硬截断；WorkBuddy 还会定期清理 traces 文件（实测单日减少 503 个）。本工作台自 2026-09-22 起对已消失的文件归档保留（见生成时间旁的「含归档 N 条」），使累计量只增不减——此前已被清掉的历史无法恢复。 更新数据：双击 刷新用量看板.bat，或等待自动刷新（每轮对话结束时触发，节流 5 分钟）。
费用口径：「官方计价」只对有公开价格的模型（DeepSeek V4/V4.1 Flash、Qwen3.8-Flash-Next 等）按厂商公开价折算； 本机自建 Qwen（192.168.2.11）与免费额度模型计 ¥0；Hy3 / Hy4 / agnes / sensenova / spark / dots3 / intern 等为平台内置或未公开定价， 其费用只在「情景估算」中按中端 flash 价（$0.30/$1.20 每百万、缓存 $0.03）折算，仅供量级参考，非实际账单。汇率按 1 USD = 7.10 CNY。
模型识别口径（已 100% 归因）：模型名取自每次调用的 API 响应对象 {"model":"custom-local:agnes-2.0-flash", "usage":{...}}， 并按响应 id 精确去重——比系统提示里的标识句更权威，也不会被 100KB 截断影响。 （早期版本依赖 This conversation is powered by <model> 标识句，会漏掉 MCP 工具 / 终端标题 / 上下文摘要这类用精简提示的辅助调用，现已废弃该口径。）
操作类型：按 trace 中工具调用的输出体量折算（约 3.5 字符 ≈ 1 token），反映哪些操作在撑大上下文，从而推高输入 token。
性能口径：延迟＝该次 generation span 的墙钟耗时（含首字前的预填充，非 TTFT）；吐字速度＝输出 token ÷ 耗时； 峰值 RPM／TPM＝按响应 created 时间戳做 60 秒滑动窗口取最大值。性能为全量口径，不随左侧时间筛选变化。
